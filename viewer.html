Understand how the models work.

Ten lenses on the same recorded runs. Click a mark to inspect its evidence.

01 · Behavioral atlas

Where do speed and judged quality meet?

Each dot is one scored model/turn. Horizontal position is total run time; vertical position is judge score. Size shows tool count.

02 · Decision braid

How does each model move through work?

Tool steps sampled at 12 positions through each run. Curves reveal repeated phase changes; this is execution order, not time.

03 · Activity weather

When is the agent busy with tools?

Each row is a run, divided into 32 equal time bins. Fill shows the fraction of each bin covered by tool calls; red borders flag failed calls.

04 · Tool terrain

Which tools dominate the workload?

Rectangle area is summed completed call duration. Overlapping calls count separately. Switch to call count to compare frequency.

05 · Latency constellation

Are slow calls rare or routine?

Every plotted dot is a completed tool call on a log duration scale. Vertical jitter separates nearby points; red marks failed calls.

06 · Quality contours

Does a strong total hide a weak dimension?

Each line is one scored model/turn across the five judge dimensions. Missing dimensions break the line; scores are judgments, not ground truth.

07 · After the error

What action follows a failed tool call?

Links connect a failed call’s phase to the next tool action. This describes the next action; it does not prove that the error was diagnosed or repaired.

08 · Tool switchboard

Which tools keep pulling the model back?

Chord ribbons count consecutive tool transitions within each run. Loops expose repeated use; direction is recorded order, not dependency.

09 · Execution pace

Do tools arrive in bursts or steadily?

Cumulative tool starts over normalized run time. Each curve is a run; steeper segments indicate a burst of observed tool calls.

10 · Outcome matrix

Where do the two models disagree?

One column per judged task; rows separate models and rubric dimensions. Color intensity shows score on the fixed 1–5 scale.

11 · Agent flow graph

What path does each model take through the tools?

Layered graph drawing of the tool-transition digraph. Each node splits in half — left is Codex's visit share, right is Claude's; arrowed edges count consecutive transitions, dashed curves loop back to an earlier phase. Hover a node to isolate its traffic.

Getting better

Reward per turn (judge score, minus cheats and false claims, adjusted by your feedback), rolling mean with a 95% band. Pins mark when the agents were changed: a lesson adopted, an evolve run, a PR applied.

RL policy

The bandit learns how many playbook lessons help each agent per task type (posterior mean reward ± 2 sd, n uses), and which agent to route to. Picking an arm takes under a millisecond before the turn.

What to change

Fixes the judges proposed after reading the traces, ranked by support across turns × how much that dimension matters to you, with repeats of one failure type down-weighted so different problems surface. Accepted fixes become lessons fed into that model’s prompts.
