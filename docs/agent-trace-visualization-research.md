# Duo should cluster, tag and score next

The 2025-2026 field has split into two layers, and Duo is strong on only one of them. Within a single run, tools and papers have settled on a common set of views: tree, timeline or flame graph, agent graph, and a flat conversation or trajectory view. Duo covers this layer well, and its reasoning, memory and context cards go further than any commercial product found. The new layer works across many traces. An LLM reads every trace, extracts facets or failure labels, and the system embeds, clusters and labels the results. It shows them with per-cluster metrics and links back to the source traces. LangSmith, Braintrust, Datadog, Docent, Laminar, Raindrop and Galileo all shipped some version of this, and METR reports that frontier labs triage eval rollouts the same way. Research adds three more things Duo lacks: standard failure taxonomies with "decisive step" attribution (MAST, TRAIL, Who&When), per-step progress or value curves (AgentBoard, AgentPRM), and process-mining graphs across many runs (Graphectory). On the RL side, the gap is LLM-judged behavior prevalence (reward hacking, sandbagging) drawn per training step against reward. The recommended build order is: a trace cluster map, failure-mode tags with ranked decisive-step suspects, a per-step progress lane, an RL behavior-prevalence overlay, a cross-run process graph, and milestone-aligned N-run divergence. The research for this report could not reach arxiv.org or several vendor sites, so many paper-level numbers come from abstracts and snippets. The last section lists which claims are weakly sourced.

## Four single-trace views are now standard, and Duo already has the hard ones

Every major observability product still uses a span tree with a timeline as its core view. By 2026 most had added three more. The first is an **agent graph**. Langfuse took it from a LangGraph-only beta in February 2025 to GA for any framework in November 2025. In July 2026 Langfuse rebuilt it with an "Aggregated" overview mode and an "Expanded" mode that follows the trace tree ([Langfuse](https://langfuse.com/changelog/2026-07-13-graph-view-modes)). Datadog draws each agent's decision path as an interactive execution graph, with OTel span links drawn as edges ([Datadog](https://www.datadoghq.com/blog/monitor-ai-agents.md)). The second is a **flat trajectory view** that removes nesting. LangSmith shipped Trajectories on September 24, 2026, as "a flat, ordered list of messages" that can be scored and sent to annotation queues ([LangChain](https://www.langchain.com/blog/langsmith-trajectories-tracing)). Laminar, Logfire and HoneyHive have similar views. The third is **session or thread grouping** with evaluators that run per thread. LangSmith thread evaluators score "semantic intent, outcome, or trajectory" ([LangSmith docs](https://docs.langchain.com/langsmith/online-evaluations-multi-turn/index.html)), and Arize AX made sessions a first-class unit in September 2026 ([Arize](https://arize.com/blog/new-in-arize-ax-september-2026-updates/)).

A few single-trace ideas stand out. HoneyHive's **trajectory bubble chart** puts span type on Y and step on X, sizes bubbles by duration and colors them green to red, which shows repeated tool calls and rising latency at a glance ([HoneyHive](https://docs.honeyhive.ai/v2/tracing/trajectory-view)). Langfuse separates **tools offered to the model from tools actually called** ([Langfuse](https://langfuse.com/docs/observability/features/agent-graphs)). Braintrust rolls up **tokens and cost per sub-tree** ([Braintrust](https://www.braintrust.dev/docs/reference/release-notes)). Laminar syncs **browser screen recordings** to spans ([Laminar](https://laminar.sh/docs/tracing/browser-agent-observability.md)). Arize's Path view reportedly breaks on looping agents, and an Arize engineer suggested a pruned Sankey instead ([Arize community](https://community.arize.com/x/arize-ax-support/msg_64zITE046XqB/path-visualization-in-arize-agen)). That is a warning for any graph Duo draws over loop-heavy runs.

Academic visual-analytics systems use the same overall layout: a hierarchical timeline or swimlanes, an action graph and a detail panel. AgentLens (IEEE TVCG) offers hierarchical temporal summaries ([PubMed](https://pubmed.ncbi.nlm.nih.gov/38700975)). AGDebugger (CHI 2025) adds message edit and reset, which a **14-participant study** found important for debugging ([arXiv 2503.02068](https://arxiv.org/abs/2503.02068)). Agent ATO (VISSOFT 2026) colors coding-agent steps into Discovery, Reading, Writing and Execution, with an aligned token track ([arXiv 2609.08301](https://arxiv.org/html/2609.08301v1)). Measured against this layer, Duo's tree and railway timelines, its two-model diff, and its loop, burst and stall detection are already at or above parity. Its context stack by source goes past the production state of the art: Claude Code's `/context` and Letta's Context Window Viewer show only **snapshots** of token use by category ([Letta](https://docs-v1.letta.com/guides/ade/context-window-viewer); [Danny Willems](https://dannywillems.github.io/2026/01/16/claude-code-context-command.html)). No product found during this research offered a timeline of context composition or memory reads and writes. The single-trace gaps Duo might still have are small: a flat transcript view, if it lacks one, and an offered-vs-invoked tools panel.

## The real shift is LLM-read clustering across thousands of traces

What is genuinely new in 2025-2026 is that an LLM reads every trace and the system groups the results. Products converged on one recipe on their own: **extract facets per trace, embed them, reduce with UMAP, cluster with HDBSCAN or k-means, and label clusters with an LLM**. Braintrust Topics extracts Task, Sentiment and Issues facets daily and offers HDBSCAN or K-Means over UMAP or PCA. It writes labels back to the logs table so they can be queried in SQL ([Braintrust](https://www.braintrust.dev/docs/observe/topics)). Datadog Patterns uses UMAP and HDBSCAN. It shows latency, eval and cost per cluster, flags "NEW" topics, and **highlights clusters with no eval coverage** ([Datadog](https://docs.datadoghq.com/llm_observability/investigate/patterns/)). LangSmith's Insights Agent can **compute a new attribute on the fly** ("user is frustrated") and then cluster by it ([LangChain](https://blog.langchain.com/from-traces-to-insights-understanding-agent-behavior-at-scale)). Anthropic's Clio defined this pipeline for chat usage in December 2024 ([Clio](https://assets.anthropic.com/m/7e1ab885d1b24176/original/Clio-Privacy-Preserving-Insights-into-Real-World-AI-Use.pdf)). METR reports that OpenAI uses an internal tool to cluster eval-rollout behaviors, and that unusual behavior is usually found through manual review or clustering, then flagged for a human to inspect ([METR](https://metr.org/blog/2026-05-19-frontier-risk-report/)).

The evidence for this approach comes from case studies, not controlled studies, but the case studies are concrete. Docent clustered why an agent got stuck on InterCode and found missing packages. Fixing them raised GPT-4o's solve rate from **68.6% to 78%** ([LessWrong](https://www.lesswrong.com/posts/Mj276hooL3Mncs3uv/analyzing-long-agent-transcripts-docent)). In Transluce's o3 truthfulness investigation, search and clustering found **71 cases** of the model claiming to have run code on an external laptop ([Transluce](https://transluce.org/investigating-o3-truthfulness)). Transluce also warns that its summaries often contain false positives ([Transluce](https://transluce.org/docent/blog/introducing-docent)), so every cluster must link back to verbatim traces. Docent has also moved on. Its docs now say "We no longer recommend search and clustering as a primary workflow." They recommend agent-written Python "Analysis Plans" that combine deterministic metadata queries with per-transcript LLM reading steps ([Docent](https://docs.transluce.org/analysis/analysis-plans)). The worked example is diagnosing why GPT-5.1 Codex underperformed GPT-5 Codex on Terminal-Bench. That is a model-comparison question, and Duo's users ask the same kind. Clustering is the visible output, and a reproducible analysis program is where the field is heading.

Process mining complements clustering. It works best on many runs of the same task. Graphectory turns linear SWE-agent and OpenHands logs into graphs and finds that **even successful agents often follow inefficient processes** ([arXiv 2512.02393](https://arxiv.org/abs/2512.02393)). Agent Mentor mines a workflow across runs of one prompt and clusters final-answer outputs to link patterns with outcomes ([arXiv 2604.10513](https://arxiv.org/html/2604.10513v1)). One cheap signal suits any map: across OpenHands, SWE-agent and Prometheus, **failed trajectories are consistently longer and more variable** than successful ones ([arXiv 2511.00197](https://arxiv.org/html/2511.00197)).

## Failure attribution exists as taxonomies and scores, but it is only 11-14% accurate

Research has produced shared vocabularies for what went wrong. **MAST** defines 14 multi-agent failure modes in three categories: specification issues, inter-agent misalignment and task verification. It was built from more than 150 traces with **κ = 0.88** agreement, then scaled with an o1 annotator ([NeurIPS 2025](https://neurips.cc/virtual/2025/poster/121528)). **TRAIL** labels 841 errors in 148 OTel-structured GAIA and SWE-Bench traces as reasoning, execution or planning errors ([arXiv 2505.08638](https://arxiv.org/html/2505.08638v3)). These lists are ready to use as tag sets for Duo's verdict card and step badges.

Finding *which* step was decisive is much harder. On TRAIL the best model, Gemini-2.5-Pro, reaches **11% joint accuracy** ([arXiv 2505.08638](https://arxiv.org/html/2505.08638v3)). On Who&When, LLM judges reach about **14% step-level accuracy** ([arXiv 2505.00212](https://arxiv.org/pdf/2505.00212)). The field's answer is intervention: replay the run with one step changed (AgenTracer, Causal Agent Replay, EMFA) ([ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/file/134ed7a477770f227f12450ef0cbb8f4-Paper-Conference.pdf); [arXiv 2606.08275](https://arxiv.org/html/2606.08275v1); [arXiv 2610.11600](https://arxiv.org/html/2610.11600v1)). Critics point out that changing one step changes everything downstream, so a single replay is unstable ([arXiv 2607.07989](https://arxiv.org/html/2607.07989v1)). TelemetrySuffBench asks a question that comes before attribution: did the trace log enough to diagnose the failure at all ([arXiv 2608.07899](https://arxiv.org/pdf/2608.07899))? For Duo, this means "decisive step" should be shown as **ranked suspects with confidence**, confirmed by replay over several samples where possible. A trace with missing tool outputs should carry a visible "insufficient telemetry" flag instead of a confident verdict.

Per-step scores turn a binary outcome into a curve. AgentBoard's **progress rate** (the share of annotated subgoals reached) shows DeepSeek-67b at **32.2% progress but only 11.3% success** on hard tasks. In its slides, a per-step curve climbs to 1.0 progress while success stays at zero ([NeurIPS 2024](https://neurips.cc/virtual/2024/oral/98026); [slides](https://neurips.cc/media/neurips-2024/Slides/98026.pdf)). AgentPRM scores each step's "promise" and "progress" with a TD-trained process reward model ([arXiv 2511.08325](https://arxiv.org/html/2511.08325v1)). "Automata from Agent Traces" finds that **most SWE-agent failures appear suddenly, not gradually**, with "stuck in edit loop" and "gave up early" as distinct modes ([arXiv 2608.23670](https://arxiv.org/pdf/2608.23670)). A cliff in a value curve is therefore a natural candidate for the decisive step, and it pairs directly with Duo's existing stall and loop detectors.

## Reasoning views need anchors and caveats; RL views need judged behavior over reward

For reasoning, the most practical new method is **Thought Anchors**. It resamples a chain of thought from each sentence onward, with the sentence kept or replaced, and measures how much the final-answer distribution shifts. It finds that a few planning and backtracking sentences act as anchors, and its open-source tool draws them as prominent nodes in a DAG ([arXiv 2506.19143](https://arxiv.org/html/2506.19143v4)). It needs only sampling access, not weights, but it costs many resamples per sentence, so it is an offline analysis. ReasoningLens and ReTrace label reasoning steps as forward, backtrack and verification, and ReTrace links every LLM-made group back to the verbatim text ([arXiv 2606.23404](https://arxiv.org/pdf/2606.23404); [arXiv 2511.11187](https://arxiv.org/pdf/2511.11187)). Faithfulness results argue for a caveat on every reasoning card. Claude 3.7 Sonnet verbalized a hint that changed its answer only **25%** of the time, and DeepSeek R1 **39%** ([arXiv 2505.05410](https://arxiv.org/pdf/2505.05410)). OpenAI showed that training against a CoT monitor produces **obfuscated reward hacking** ([arXiv 2503.11926](https://arxiv.org/abs/2503.11926)).

Duo's memory and context cards are ahead of every product found. One refinement is supported by research. Chroma's context-rot study of 18 models finds accuracy declines gradually as input length grows, **well below the window limit** ([ZenML summary](https://www.zenml.io/llmops-database/context-rot-evaluating-llm-performance-degradation-with-increasing-input-tokens)). So a fill line alone understates risk. Two additions would cost little: compaction and tool-result-clearing markers on the context stack, since Anthropic's API now exposes both as named primitives ([Claude cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)), and a "quality risk" band. Chroma sells a vector database, which is a conflict of interest to note.

For RL, the standard dashboard is mature. Frameworks log reward and per-component reward, reward std, response length, entropy and KL ([veRL](https://mintlify.wiki/verl-project/verl/reference/experiment-tracking); [TRL](https://huggingface.co/docs/trl/v0.18.0/en/logging)). Rising length is a known sign of length hacking. Entropy collapse predicts the performance ceiling through R = −a·exp(H) + b ([Entropy Mechanism](https://huggingface.co/papers/2505.22617)). Duo's reward curves with pass@k and pass^k match τ-bench's reliability framing, in which GPT-4o dropped to about **25% pass^8** on τ-retail ([arXiv 2406.12045](https://arxiv.org/pdf/2406.12045)). ReliabilityBench notes that pass^k equals (pass^1)^k only when failures are independent ([arXiv 2601.06112](https://arxiv.org/pdf/2601.06112)), so Duo can usefully plot observed pass^k against the independence prediction. The emerging view puts **LLM-judged behavior prevalence per training step** on top of the reward curve. METR's MALT shows that prompted monitors reach **AUROC 0.96 for reward hacking and 0.91 for sandbagging** across 10,919 labeled transcripts ([METR](https://metr.org/blog/2025-10-14-malt-dataset-of-natural-and-prompted-behaviors/)). Docent lets users plot hack counts across training steps ([LessWrong](https://www.lesswrong.com/posts/Mj276hooL3Mncs3uv/analyzing-long-agent-transcripts-docent)). When reward rises while judged-legitimate success stays flat, reward hacking shows up as a gap between two lines.

## Prioritized build list for Duo

The table ranks six methods Duo lacks. The ranking weighs how many independent tools or papers converge on each method, how strong the evidence is, and how much it extends Duo's current strengths.

| # | Method | What to draw | Data it needs | Why it matters |
|---|---|---|---|---|
| 1 | **Trace cluster map with per-cluster metrics** | 2-D UMAP scatter of runs colored by cluster, with a side list of LLM-labeled clusters (hierarchical, Clio style) showing count, pass rate, mean cost and length. Add a "NEW since last period" flag and a "no labeled-benchmark coverage" flag. Each cluster opens its verbatim runs. | One LLM-written facet summary per run (intent, outcome, failure reason), embeddings, HDBSCAN or k-means, an LLM labeler, and the run metadata Duo already has. | It is the most convergent new method of 2025-2026 (Braintrust, Datadog, LangSmith, Docent, Clio, frontier-lab practice per METR). It turns Duo's significance-tested trends into answers about *why* runs fail. |
| 2 | **Failure-mode tags and ranked decisive-step suspects** | MAST and TRAIL badges on steps in the tree and railway views. A heatmap of failure mode by model or agent. In the verdict card, the top 3 suspected decisive steps with confidence, plus an "insufficient telemetry" warning when tool outputs or messages are missing. | An LLM tagger with the MAST/TRAIL vocabulary, per-step judge scores, and a completeness check on logged fields. MAST's open annotator and TRAIL's dataset can calibrate it against Duo's labelled benchmark. | Shared taxonomies make results comparable across models. The 11-14% judge accuracy is exactly why ranked suspects with confidence beat a single verdict. |
| 3 | **Per-step progress / value lane** | A sparkline under the railway timeline showing progress rate or PRM value per step, with sharp drops marked. Overlay it on Duo's stall and loop markers, and draw it in the two-model diff so the curves can be compared directly. | Subgoal checklists per task (AgentBoard style) or a step judge or PRM. Make it a pluggable score channel. | It separates near-misses from flat failures (32.2% progress vs 11.3% success in AgentBoard) and points to the sudden-failure cliff that 2608.23670 reports. |
| 4 | **RL behavior-prevalence overlay** | On the reward-curve page, add aligned panels: reward and pass^k vs step, judged hack, sandbagging and test-skipping rate vs step, plus response length and entropy. Plot observed pass^k against the (pass^1)^k independence prediction. Clicking an inflection opens example rollouts. | Sampled rollouts per step (veRL warns that tracing every sample is huge, so sample), an LLM monitor prompt (MALT style), and the framework's length and entropy scalars. | It makes reward hacking visible as reward diverging from judged-legitimate success. Monitors are good (AUROC 0.96), and CoT-monitor work shows why this belongs in eval views, not in the reward. |
| 5 | **Cross-run process graph** | A deduplicated directed graph of actions or tool signatures across all runs of one task, with node size for frequency, edge width for transitions, and color for the success rate of runs passing through. Use a pruned Sankey or loop-collapse fallback when cycles dominate. | Normalized action signatures per step (tool name plus argument class). OTel `execute_tool` and `gen_ai.tool.name` make this portable across frameworks. | Graphectory shows inefficiency even in successful runs. Langfuse's aggregated graph, HoneyHive's weighted graph and Arize's logical flow map all converge here. It extends Duo's per-run loop detection to the population. |
| 6 | **Milestone-aligned N-run divergence with fork-replay** | Extend the step-aligned two-model diff to N runs aligned on milestones rather than step index, mark the first divergence, and branch into outcome bands. Add a "fork from here" action that reruns k samples and reports the outcome distribution. | Milestone extraction (an LLM or tool-call signatures), repeated runs per task, and replay hooks in the harness. | InconLens and AGDebugger both found divergence localization and resets central to debugging. Reporting replay as a distribution answers the instability criticism of counterfactual attribution. |

Three smaller items are worth adding when convenient: compaction and tool-clearing markers plus a context-rot risk band on the existing context stack; a Thought-Anchors-style sentence-importance heatmap as an offline job on Duo's reasoning bars; and a trace-scoped assistant like LangSmith Chat, Braintrust Loop or Arize Alyx. The assistant is common in products, but it adds little that items 1 and 2 do not, unless it produces reproducible analysis programs the way Docent's plans do.

## Where the evidence is thin

Several findings rest on weak sources and should be checked before anyone relies on them. arxiv.org was unreachable, so every arXiv-only claim comes from abstracts, HTML snippets or secondary summaries. This applies most to the 2026 preprints (InconLens, Graphectory Viewer, Automata from Agent Traces, Causal Agent Replay, EMFA, TelemetrySuffBench, ReasoningLens, TraceView, Agent ATO) and to Thought Anchors' models and effect sizes, which were not verified. MAST's scale conflicts between sources (more than 1,000 vs more than 1,600 traces). Langfuse and LangSmith pages could not be opened, so their UI details come from search summaries. Braintrust's 2025 release weeks, whether OSS Phoenix has an agent graph, and the details of Galileo's and Opik's views are all unverified. The recall figures for CoT monitors (about 95% vs 60%) and the Clip-Cov entropy gains come from secondary summaries and are left out above. Third-party claims about Claude Code's auto-compaction threshold conflict. No source offered controlled user studies showing that cluster maps, PRM overlays or diff designs improve debugging over plain trace lists. The supporting evidence is case studies and small expert studies of 5 to 14 users. Vendor comparisons were all written by vendors.

## Conclusion

The field has moved from the question "what happened in this run?" to "what keeps happening across runs, and is it real?" Duo already answers the first question better than most products. The highest-value next step is to put an LLM-reading layer on top of Duo's existing data, not to add another single-run chart. That layer needs to be calibrated, which most products do not do. Duo's labelled benchmark is a real advantage here. It can measure the accuracy of the cluster labels, failure tags and decisive-step suspects that competitors show without any calibration. Given 11-14% attribution accuracy and frequent summary false positives, measuring accuracy is the minimum requirement for these features to be trustworthy.

Docent's deprecation of interactive clustering in favor of agent-written analysis plans points one step further. Within a year or two, the best "visualization" for a model-comparison question will likely be a reproducible program whose charts are its output. If Duo builds items 1 to 4 on a queryable per-run facet table rather than as fixed widgets, it can follow that path without a rewrite.
